# WinUI-BBS 使用与配置

[返回项目首页](../README.md) · [English](configuration.en.md)

**当前版本：0.2.2** · **开源许可：GPL-3.0-only**

WinUI-BBS 是一个采用 WinUI 风格的开源论坛系统，使用 Vue 3、WinUIonWeb、Fastify 和 PostgreSQL 构建。它提供可视化管理后台、用户组权限、分级板块、图文发帖、内容审核、站内通知与个人图床。

## 本地运行

1. 安装 Node.js 22.12 或更新版本、PostgreSQL 17 或更新版本。
2. 创建名为 `forum` 的 PostgreSQL 数据库，以及供应用使用的数据库账号。
3. 将 `apps/api/.env.example` 复制为 `apps/api/.env`，填写数据库连接串 `DATABASE_URL` 和私有的 `JWT_SECRET`。
4. 在仓库根目录安装依赖并启动服务：

   ```powershell
   npm install
   npm run dev
   ```

5. 打开 <http://127.0.0.1:5173/>。空库首次访问会引导创建站点管理员，之后通过登录对话框进入社区。

API 默认监听 <http://127.0.0.1:4000/>，健康检查地址为 `/api/health`。启动时按文件名顺序应用 `apps/api/migrations/` 中的 SQL 迁移，已执行迁移保存在 `schema_migrations` 中。上传文件存放在 `apps/api/data/uploads/`。

环境配置示例见 [apps/api/.env.example](../apps/api/.env.example)。真实环境配置、上传文件、构建产物和本地验收资料均不应提交到仓库。

## 更新已有部署

一键安装的实例可在“站点设置 → 系统更新”选择正式或预发布渠道并启用自动更新；安装、发布及恢复说明见[构建、发布与更新](releases.md)。源码部署继续使用下述手动更新方式。

更新代码前备份 PostgreSQL 数据库、本地上传目录和部署配置；使用对象存储时同时保留对应存储桶。保留原 `MAIL_ENCRYPTION_KEY` 和 `STORAGE_ENCRYPTION_KEY`，以便继续读取已加密的凭据。更新后执行 `npm ci`、`npm run check` 和 `npm run build`，再重启服务；API 会自动应用尚未执行的迁移，无须重新初始化数据库。

迁移会保护当前头像和现有表情、站点图标；之后上传的头像即使更换也会保留回收保护。旧版本已更换的头像没有独立身份记录，因此仍按普通图库图片处理。

## 主要功能

手机端标题栏隐藏站点名称与“社区”文字，保留图标、导航、搜索、主题和账户入口，为搜索框留出空间。搜索需输入 1–120 字非空白关键词；手机端按 Enter 提交，空白搜索不会跳转，直接访问空搜索页只显示输入提示，API 拒绝空白关键词。

- **用户与身份**：UID 从 1 开始，同时保留 UUID；支持多个用户组、临时成员关系、头像、昵称和用户名修改。
- **用户组与权限**：普通、公开用户组不能拥有管理类权限；管理用户组固定保留发帖、回复、使用图床权限，并至少拥有一项管理类权限。临时、特殊用户组继续按配置授权。
- **等级与经验**：签到、发帖和回复可获得经验；后台可以设置升级所需经验、奖励规则、等级头衔和用户等级。
- **板块结构**：树形板块支持拖动排序、自定义图标、可选通知徽标，以及独立的阅读和发帖等级限制。
- **图文编辑**：Editor.js 块编辑器采用中文界面，支持图片、引用、列表、代码、行内剧透和表情包。
- **内容管理**：发帖管理、发帖审核、个人回收站、管理员删除记录和按身份去重的浏览量。
- **站内消息**：向全体用户、指定用户组或 UID 发送公告与通知，支持未读徽标和已读状态。
- **外观与关于**：浅色、深色主题、强调色、紧凑导航和文字缩放；“关于”页展示项目介绍、版本及开源项目链接。

## 用户、注册与邀请码

管理后台使用分层导航：“用户与注册”“内容管理”“站点配置”的父项只展开或收起子树，点击子项才打开页面。仅显示当前用户有权限的子项；没有可访问子项的分组不显示。导航窗格切换按钮位于 TitleBar 左侧，桌面可展开或折叠，窄屏可打开或关闭抽屉。

### 邮箱验证与密码安全

“站点配置 → 发信设置”配置 SMTP 发信以及可选的 IMAP 收信连接检查。SMTP 负责发送邮件，IMAP 不用于发信。支持直接 TLS（常用端口 465）和 SMTP STARTTLS。填写发件身份、服务器、端口、账号和密码后保存，可发送测试邮件或检查 IMAP 连接。已保存的密码不回传前端，密码框留空会保留原凭据。

首次配置发信凭据前，在 `apps/api/.env` 设置 `MAIL_ENCRYPTION_KEY`。可以使用以下命令生成 32 字节 Base64 密钥，将输出保存为该环境变量；以后需要保留同一密钥以读取已保存凭据：

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

邮件凭据使用 AES-256-GCM 加密后保存在数据库中。真实邮箱、服务器和凭据属于本地部署配置，不应写入源码、截图或 Git 仓库。

在“用户与注册 → 注册管理”启用注册邮箱验证后，注册需要先取得邮箱验证码。验证码默认有效 **60 分钟**；同一邮箱的注册、改密和找回邮件共用发送间隔，默认 **60 秒**，不能设置得更短。验证码一次性使用，输错 5 次后失效。

登录对话框提供“找回密码”。用户填写注册邮箱后会收到一次性找回链接，默认有效 **30 分钟**，同一邮箱每天最多请求 **1 次**；次数按站点时区计算。链接使用“站点设置”中的站点 URL，请将其设为用户实际能访问的地址。重设密码后，所有旧登录凭证失效。

用户后台的“更改密码”通过已绑定邮箱的验证码确认身份，新密码需为 10–128 位。默认每 **60 秒**最多成功修改一次。改密后保留当前登录，其他旧登录凭证失效。

验证码有效期、发送间隔、找回功能开关、链接有效期、每日找回次数及改密间隔均在注册管理中配置。注册邮箱验证默认关闭，以保留未配置邮件服务时的现有注册方式；启用前必须先配置发信服务。上述流程不会向已有账号补加登录邮箱验证要求。

注册可以关闭、向所有人开放，或要求邀请码。管理员可以创建单次或多次使用的邀请码，设置等级奖励，并启用、停用或删除奖励规则。删除奖励规则后，已经发出的邀请码仍然保留。用户可从用户后台中的“我的邀请码”管理邀请链接；复制邀请与图片链接时使用配置的站点 URL。

用户可以上传头像、修改昵称和登录用户名。用户名不区分大小写，成功修改后需等待 180 天才能再次修改；有效管理用户组成员豁免此限制。失败的修改和保存相同用户名不占用次数。昵称独立修改，并用于顶栏、个人资料和帖子署名。更换用户名不会改变 UID、昵称或其他账号数据。

管理员可以将账号封禁 30 分钟至 1095 天，或提前解封。临时封禁期间仍可登录，以最低用户阅读等级 Lv.1 浏览，并查看自己的资料、帖子、收藏夹和图片。所有写操作（包括点赞、发帖、回复、收藏、上传、改资料和签到）及管理后台访问被禁止，到期自动恢复原权限。永久停用是独立状态，仍禁止登录。

## 正文限制、分页与本地草稿

在“内容管理 → 发帖与回复设置”配置以下限制，需要 `settings.manage` 权限。前后端共同校验，新设置用于之后提交的内容，不删改历史正文。

| 项目             | 默认值 | 允许范围 |
| ---------------- | ------ | -------- |
| 帖子正文字数     | 20000  | 1–100000 |
| 帖子正文普通图片 | 15     | 0–50     |
| 回复字数         | 1000   | 1–10000  |
| 回复普通图片     | 5      | 0–20     |
| 每页回复         | 20     | 1–100    |

字数按 Unicode 字符计算，包含列表、引用、图片说明等可见正文，格式标记不占字数。图片上限只计算普通图片，用户上传表情、远端行内表情和社区表情不占此额度；所有表情合计固定最多 1000 个，每篇帖子、每条回复（含楼中楼）独立计数，重复插入也逐个计数。回复在服务器分页，帖子和回收站详情均支持翻页。

编辑器中的待发正文、标题、板块和图片仅缓存在当前浏览器 IndexedDB，按用户和回复目标隔离；刷新或返回页面可恢复，清除浏览器站点数据会删除草稿。选图时使用本地预览，提交帖子或回复时才将新图片与正文一起发送。验证、容量检查或保存失败会回滚图片文件与记录，草稿保留；提交成功后清除对应草稿。每次提交的新图片总大小最多 100 MiB，并受个人媒体额度约束。

从板块页点击“发布帖子”时，发帖页自动选择该板块，并优先于草稿保存的板块；草稿标题、正文和图片继续恢复。用户仍可手动更换板块。从普通入口进入时沿用草稿板块，无草稿时选择第一个允许发帖的板块；等级不允许的板块不能预选。

“我的图片”默认只能管理已上传的正文图片，不能直接上传图床图片。管理员可在同一设置页开启直接上传；头像和表情包仍使用各自的上传入口。

## 回复、楼中楼与删除

在帖子回复下方点“回复”可展开楼中楼编辑器；回复某一条楼中楼时会显示被回复用户名。每个主回复每页显示 5 条楼中楼，提供上一页、下一页和页码跳转；分页只刷新当前楼层，不切换帖子回复页。每条主回复和楼中楼都有独立楼层号，格式为“第 12 楼”和“第 12 楼-3 层”。楼层分配按时间递增且不回收；永久删除后后续楼层号仍连续增长，历史编号不重新排列。已删除回复不显示楼层号，但保留其占用的编号。

普通用户只会看到自己回复上的删除按钮，并且只能删除自己发表的内容。拥有 `posts.manage` 的管理员可以删除任意回复。删除不进入回收站，也无法恢复；删除有楼中楼的主回复时可选择仅删除主回复（保留楼中楼，显示“该回复已被管理员删除”）或删除整层。管理员删除会向受影响作者发站内通知并写入管理记录；作者自行删除不会发送管理通知或写入管理员操作记录。删除最后一条楼中楼后，如果其主回复此前已删除，会一并清理空的删除占位。

## 关注与隐藏段落

在帖子作者旁或用户空间顶部资料卡右侧点“关注”，即可在“用户后台 → 我的关注”（`/account/following`）浏览关注的用户并进入其空间，也可取消关注。社区首页保留置顶帖优先，其后优先显示关注作者的未读帖子；登录后打开详情即计为已读，刷新、点赞和翻页不重复计数。已读帖子回到原排序，作者之后发布的新帖仍会优先。板块、搜索和热门讨论保留各自排序。

用户空间资料卡显示该用户当前粉丝数，关注或取消关注后更新；游客也可查看。

发帖时选中文字，右键选择“内容锁定…”，在对话框中选择“回复后解锁”“点赞后解锁”或“关注后解锁”。每段使用一种条件，可选择跨段文字；再次选中锁定文字可更改条件或移除锁定。草稿保留文字和条件。回复编辑器不提供内容锁定。

`posts.hide_content` 控制隐藏段落权限，普通用户组默认拥有，可在“用户组与权限”中调整。无权限时编辑器隐藏锁定入口，API 同时检查有效组权限。作者可阅读自己的全部内容；其他用户在有未删除回复（含楼中楼）、当前点赞或当前关注作者时解锁对应段落。取消点赞、取消关注或删除最后一条有效回复后，相应内容重新锁定。游客需先登录。此功能与点按即显示的“剧透”标记独立。

未解锁正文由 API 移除受保护文字、链接及其他属性。社区列表摘要、搜索、用户空间和收藏夹列表始终隐藏这些片段；满足条件后在帖子详情阅读。新迁移 `015_follows_and_content_locks.sql` 创建关注关系，并为已有普通组、管理组添加隐藏段落权限；API 启动时自动执行。

## 收藏与用户空间

用户后台的“我的收藏”按钮进入二级页面，可创建、重命名、删除收藏夹，设置是否公开，以及移动或取消收藏。每人最多 100 个收藏夹，名称 1–64 字。

在收藏夹列表点击“设为默认”，或在新建、编辑时开启“设为默认收藏夹”。每人最多一个默认夹；删除它后需要重新选择。未收藏时，帖子收藏拆分按钮左侧会快速保存到默认夹，未设置默认夹时打开选择菜单；已收藏时，再次点击左侧会从自己的所有收藏夹中移除此帖。右侧下拉菜单可单独选择其他收藏夹、取消收藏，或新建收藏夹。收藏到任一夹后，按钮显示强调色“已收藏”；全部取消后恢复普通色“收藏”。点赞使用切换按钮，点赞后显示强调色，刷新后保留状态。

点击帖子列表、帖子正文署名或回复的用户头像可打开 `/users/:uid` 用户空间。空间仅显示已发布且访客有阅读权限的帖子，以及公开收藏夹；隐藏、删除、待审和被拒绝帖子不会出现在空间和公开收藏中。私密收藏夹只有本人可读取。收藏夹公开内容也遵循访客阅读等级，公开计数不包含不可读帖子。

## 发帖管理与回收站

作者可在用户后台将自己的帖子移入个人回收站。回收站中的帖子和原有回复仅作者可见，并从公开列表和发帖管理中排除。恢复后保留原有发布或审核状态、点赞和回复，不重复发放经验。

回收站默认保留 30 天，可在“站点设置 → 回收站”调整。新配置仅影响之后删除的帖子，已有到期时间不变。到期后立即停止访问与恢复；API 在启动时及之后每小时清理到期记录。图片仍由个人图床独立管理。

“发帖管理”中的隐藏操作会将帖子从首页、热门、搜索和板块列表中移除，持有 URL 的用户仍可在满足阅读等级条件时访问。管理员删除的帖子进入独立“删除记录”，仅拥有 `posts.manage` 的用户可恢复，不进入作者回收站，不自动到期，恢复时保留原状态。

`posts.set_reader_level` 控制是否可以为新帖设定大于 0 的最低阅读等级，前后端共同校验。管理组初始拥有此权限，普通组默认不拥有。

浏览量按登录账号或持有签名 `forum-visitor` Cookie 的游客浏览器去重。反复打开、刷新和点赞不会重复增加浏览量。登录身份和游客身份分开计数；更换浏览器或清除 Cookie 会形成新的游客身份。历史浏览总量保留，后续访问按新规则去重。

## 发帖审核与通知

在“审核设置 → 全站发帖审核”中启用新帖审核，也可在“板块结构”中单独为某一板块启用。更改设置只影响新提交的帖子，已有帖子和待审队列保持原状态。

审核规则按以下顺序应用：

1. 拥有 `posts.require_review`（发帖必须审核）的用户始终需要审核，即使同时拥有免审核权限。
2. 其余拥有 `posts.bypass_review`（发帖全局免审核）的用户可直接发布。
3. 其余用户在全站或当前板块启用审核时进入待审队列。

`posts.review` 授予发帖审核权限。审核员可阅读正文，查看作者、发帖时间、当前用户组与提交 IP，并通过、填写原因拒绝，或拒绝并临时封禁作者。历史帖子未记录提交 IP。拒绝和封禁会同时生成私有站内通知；临时封禁账号保持只读访问。

内置“站点管理”组初始拥有审核与免审核权限；新建管理组使用为其选择的管理权限。仅有 `posts.manage` 的用户不能通过发帖管理接口发布待审或被拒绝的内容。作者可通过帖子 URL 阅读自己的待审、被拒绝内容，审核员通过审核界面阅读。

用户组权限迁移会移除普通、公开组已有的管理权限，为管理组补齐三项基础用户权限，并将没有任何管理权限的旧管理组转为特殊组，保留成员关系与既有能力。移除授权和变更类型会记录在管理日志中。

拥有 `settings.manage` 的管理员可在“公告与通知”中向当前所有活跃账号、某个有效用户组的成员，或指定 UID 发出消息。用户在“站内通知”中阅读公告和审核结果，可标记单条或全部已读、加载较早消息。未读徽标每 30 秒更新。新注册用户不会收到注册前发送的公告。

## 图床与表情包

“图床与表情 → 上传与远端设置”可调整默认限额：每用户 1 GiB、单图 20 MiB、20 组个人表情包、个人上传每组 150 张、单张表情 3 MiB。用户组可覆盖各项限额；多个有效组同时配置时，每项取最大值，未覆盖项使用站点默认值。`media.use` 控制个人图床管理与上传权限，普通成员默认拥有。

“图床与表情 → 存储设置”显示本站在每个存储后端的已用、剩余和容量，以及服务器各逻辑磁盘的剩余空间。管理员可设置本地最大可用容量、优先使用本地或对象存储、对象存储的本站配额，以及空间不足时每批回收的普通图片容量（默认 500 MiB）。本地容量设为 0 时使用上传目录所在磁盘的可用空间；优先后端没有足够空间时自动切换到另一个已启用后端。

对象存储支持兼容 S3 的 API。填写端点、Bucket、区域、路径前缀、Access Key、Secret Key 和本站配额后，可先执行连接测试，再保存设置。凭据使用 `STORAGE_ENCRYPTION_KEY` 加密保存；未设置时复用 `MAIL_ENCRYPTION_KEY`。每个文件会记录上传时使用的对象存储配置，因此修改或关闭当前配置不会使已有图片地址失效。对象存储容量按管理员填写的本站配额统计，不会把同一 Bucket 中其他应用的对象算入本站。

存储或所在磁盘达到 95% 时，系统向拥有 `media.manage` 的有效管理员发送站内提醒；对象存储达到 95% 时同样提醒。提醒每个后端每天最多发送一次，容量恢复后会重新进入提醒周期。所有已启用后端都放不下新图片时，系统从最早上传的普通图片开始按设定批量回收，并将正文中的引用替换为删除占位图；表情包、头像和站点图标永不参与自动回收。回收会写入管理记录，S3 删除失败时会保留待删除队列，后台维护任务会重试。

“我的图片”支持已上传图片的说明编辑、链接复制、个人表情包及远端表情包收藏。个人表情包仅出现在作者的编辑器选择器中。删除自有图片时，现有帖子和回复中的对应图片位置会替换为阿卡林占位图，其他图片和说明保持原样；删除个人上传的表情包也会替换对应引用。当前头像与站点图标受到删除保护。

在“我的图片 → 我的表情包”查看分组预览，用“上移 / 下移”保存个人分组顺序。编辑器选择器使用 PipsPager 切换分组，指针在面板内滚动滚轮可切组。超过 20 张的组先在组内滚动，到顶或到底后继续同向滚动一段距离才切换至上一组或下一组，切组后会抑制惯性连续跳组。悬停或聚焦表情时显示名称。

远端表情插入在当前光标处，与文字同行，高度为当前字号的两倍（正文默认约 30px）。可连续插入、逐个退格或 Delete 删除，支持撤销和草稿恢复；个人上传表情继续作为 80px 独立块显示。行内表情计入每篇正文固定 1000 个的表情限额，服务端校验缓存图片身份。已有远端表情块由迁移 014 标识，展示时接在前一段文字后；已有个人上传表情保持原样。

远端下载默认关闭，可在后台启用并配置兼容的 [Bmoji](https://github.com/SomeOvO/Bmoji) API。支持搜索、预览及静态/GIF 版本导入。同一来源、表情包和版本共用本地缓存，用户通过独立收藏关系使用，不计入个人图床容量。远端每组图片数由远端服务器管理，不受个人上传每组 150 张限制。“用户下载的远端表情包计入个人组数限额”默认开启；关闭后只统计个人上传组，重新开启不会移除已有分组，超额用户须先移除分组才能继续添加。移除个人收藏不会删除共享缓存或影响帖子中的表情。

管理员在“图床与表情”选择一组已有共享分组，或在“上传与远端设置”从远端下载并设为社区表情包。社区组只有一组，固定排在选择器第一位，不占任何用户的个人组数限额，用户不能排序或移除。未设置或没有图片时不显示该组。有 `posts.create` 或 `replies.create` 权限的用户可在对应发帖、回复编辑器使用，无须 `media.use`。迁移会沿用首个已有图片的共享组，初始空组保持隐藏。

“图片管理”支持按文件名、图片说明、表情包名称搜索，并与资源类型和分组筛选组合使用，默认每页 50 张。分页接口为 `GET /api/admin/media/search`，支持 `q`、`collection`、`packId`、`page` 和 `pageSize`；原媒体列表接口保留数组返回格式。

## 开发与验证

前端位于 `apps/web`，后端位于 `apps/api`。应用使用 WinUIonWeb 的 TitleBar、NavigationView、Frame、表单、对话框、树和主题资源。路由采用 Hash 模式，可以直接链接帖子、板块和管理页面；管理菜单按用户有效权限显示。

热门讨论直接展示帖子列表，不显示顶部板块卡片或发布帖子按钮；社区首页和分类页保留板块及发帖入口。

Windows 使用本机 Segoe Fluent Icons，其他系统在挂载页面前加载本地 Fluent UI System Icons，覆盖业务和控件图标，无需安装字体。新增图标需同时维护两套图标的对应关系，`npm run check` 会检查映射；维护方法见[跨系统图标](icon-compatibility.md)。

```powershell
npm run check
npm run build
npm run test:integration -w apps/api
```

集成测试使用已配置的 PostgreSQL 数据库创建临时 schema，并在运行后移除，覆盖注册、邀请码、媒体权限与限额、共享远端缓存、用户组约束、封禁、审核、通知、占位图片和回收站隔离。测试数据库账号需要创建 schema 的权限。

前端格式化命令为 `npm run format -w apps/web`。独立前端验收实例可通过 `FORUM_API_URL` 将 Vite 代理指向独立测试 API。
