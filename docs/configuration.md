# WinUI-BBS 使用与配置

[返回项目首页](../README.md) · [English](configuration.en.md)

**当前版本：1.0.3** · **开源许可：GPL-3.0-only**

WinUI-BBS 是一个采用 WinUI 风格的开源论坛系统，使用 Vue 3、WinUIonWeb、Fastify 和 PostgreSQL 构建。它提供可视化管理后台、用户组权限、分级板块、图文发帖、内容审核、站内通知与个人图床。

## 本地运行

1. 安装 Node.js 22.12 或更新版本、PostgreSQL 17 或更新版本。
2. 创建名为 `forum` 的 PostgreSQL 数据库，以及供应用使用的数据库账号。
3. 将 `apps/api/.env.example` 复制为 `apps/api/.env`，填写数据库连接串 `DATABASE_URL` 和私有的 `JWT_SECRET`。
4. 在仓库根目录安装依赖并启动服务：

   ```powershell
   npm install
   npm run dev
   ```

5. 在 API 启动日志中找到“首次安装”安全入口，使用该完整地址创建站点管理员。普通首页只显示准备状态；创建完成后入口立即失效。未完成时重启服务可在日志中找回同一入口。

API 默认监听 <http://127.0.0.1:4000/>，健康检查地址为 `/api/health`。启动时按文件名顺序应用 `apps/api/migrations/` 中的 SQL 迁移，已执行迁移保存在 `schema_migrations` 中。上传文件存放在 `apps/api/data/uploads/`。

环境配置示例见 [apps/api/.env.example](../apps/api/.env.example)。真实环境配置、上传文件、构建产物和本地验收资料均不应提交到仓库。

## 生产部署与性能

生产部署运行 `npm run build` 后，将完整的 `apps/web/dist`（包括 `.br`、`.gz` 文件）交给 `FORUM_WEB_ROOT`。内置静态服务按浏览器支持选择 Brotli、gzip 或原文件；带哈希的 `assets` 缓存一年，HTML 和无哈希文件每次使用前重新验证。

前端按路由加载页面，后台和编辑器依赖在访问相应页面时加载。WinUIonWeb 使用仓库内固定的 `0.2.0-forum.4` 包，以组件导入代替全量注册，内部图标、提示和网格列定义由控件局部导入；安全补丁移除 XAML 的动态脚本求值，将 Vue 动态字符串保留为数据。补丁与可复现构建说明见 [vendor/winuionweb/README.md](../vendor/winuionweb/README.md)。

密码计算使用至多两个工作线程，保留现有 bcrypt 哈希和 cost；等待队列达到 64 项时返回 503，稍后可重试。图片上传和发布附件在系统临时目录流式暂存，通过校验并取得存储写锁后才写入图库，成功或失败都会清理临时文件；运行账号需要临时目录的读写权限。

systemd 服务同时使用 `ProtectSystem=strict` 时，需配置 `PrivateTmp=true`，为头像、图床、表情和帖子/回复附件提供可写的独立临时目录。安装脚本已包含此项；旧安装出现 `EROFS` / `mkdtemp /tmp/forum-media-*` 错误时，按[发布与恢复指南](releases.md#修复旧安装的上传临时目录权限)添加持久覆盖配置。

### 公网部署的安全设置

上线前设置 `NODE_ENV=production`、独立随机 `JWT_SECRET`（至少 32 字节）及 HTTPS。设置 `FORUM_WEB_ROOT` 也会启用生产密钥检查；缺失、过短或仍为示例值的密钥会使启动失败。生成命令和完整反代示例见[安全部署](security.md)。Vite 开发服务器不用于公网生产服务。

登录每 IP 每分钟最多 20 次；注册和首启各每 10 分钟 5 次；发信、找回密码每条接口各每 10 分钟 10 次；重置令牌检查和提交各每 10 分钟 10 次；修改密码每分钟 5 次。超出返回 429 和 `Retry-After`。IPv6 按 /64 聚合；现有按邮箱间隔、验证码尝试次数和每日找回次数限制继续生效。多进程或多实例部署需在统一反代/网关增加共享限流。

通过反代运行时，将 `FORUM_TRUST_PROXY` 设为代理的实际 IP 或 CIDR，例如 `127.0.0.1,::1`，并阻止客户端绕过代理直连。默认不信任 `X-Forwarded-For` 和 `X-Forwarded-Proto`；不可设置为 `true` 或全网段。API 响应不缓存；内置静态服务和上传同时使用 CSP、禁止嵌入和禁止 MIME 嗅探的响应头。HTTPS 请求还返回 HSTS。

新建或修改密码时先对完整 UTF-8 密码做 SHA-256，再使用 bcrypt 加盐散列，保存为带 `$forum-sha256$v1$` 标记的格式，避免 bcrypt 的 72 字节截断。旧 bcrypt 账号仍能登录；旧密码超过 72 字节的用户应修改密码以获得完整字节校验。旧版程序不识别新标记格式，程序回退需保留支持该格式的版本，或配套恢复升级前数据库。

普通上传、发布附件和远端表情均检查图片文件头，只接受 PNG/JPEG/WebP/GIF。远端表情 JSON 最大 4 MiB，每包最多 1000 个条目、100 MiB 图片；跨源下载及每次重定向禁止访问内网、回环、链路本地及保留地址，并在连接时固定已校验的 DNS 结果。管理员明确配置的 API 同源允许自托管私网服务；该源应由可信管理员维护。

## 更新已有部署

一键安装的实例可在“站点设置 → 系统更新”选择正式或预发布渠道并启用自动更新；安装、发布及恢复说明见[构建、发布与更新](releases.md)。源码部署继续使用下述手动更新方式。

更新代码前备份 PostgreSQL 数据库、本地上传目录和部署配置；使用对象存储时同时保留对应存储桶。保留原 `MAIL_ENCRYPTION_KEY` 和 `STORAGE_ENCRYPTION_KEY`，以便继续读取已加密的凭据。更新后执行 `npm ci`、`npm run check` 和 `npm run build`，再重启服务；API 会自动应用尚未执行的迁移，无须重新初始化数据库。

迁移 `026_public_post_lists.sql` 增加公开列表与作者列表索引；`027_feed_reply_counts.sql` 回填帖子未删除回复数，并安装维护触发器及热门、板块和子回复索引。首次应用 027 会锁定相关表并回填数据、创建索引，数据量较大时应安排维护时段。之后的回复新增、软删除、恢复和永久删除均在同一事务中更新统计。

迁移 `028_two_factor_and_turnstile.sql` 增加两步验证字段和 Turnstile 配置，`029_totp_login_challenges.sql` 增加一次性登录挑战。两项功能默认关闭，已有用户继续按原方式登录。

媒体回收保护规则涵盖当前头像和现有表情、站点图标；之后上传的头像即使更换也会保留回收保护。旧版本已更换的头像没有独立身份记录，因此仍按普通图库图片处理。

## 主要功能

手机端标题栏隐藏站点名称与“社区”文字，保留图标、导航、搜索、主题和账户入口，为搜索框留出空间。搜索需输入 1–120 字非空白关键词；手机端按 Enter 提交，空白搜索不会跳转，直接访问空搜索页只显示输入提示，API 拒绝空白关键词。

- **用户与身份**：UID 从 1 开始，同时保留 UUID；支持多个用户组、临时成员关系、头像、昵称和用户名修改。
- **用户组与权限**：唯一的全局管理员用户组固定拥有全部权限，不可新建、删除、改变类型或撤销权限，可改名。UID 1 为永久成员且不可封禁或停用；全局管理员可添加其他成员，仅 UID 1 可移除其他全局管理员。旧管理用户组可删除。全局管理员发帖免审核，并享有管理组的用户名冷却豁免。普通、公开用户组不能拥有管理类权限；管理用户组固定保留发帖、回复、使用图床权限，并至少拥有一项管理类权限。临时、特殊用户组继续按配置授权。
- **等级与经验**：签到、发帖和回复可获得经验；后台可以设置升级所需经验、奖励规则、等级头衔和用户等级。
- **板块结构**：树形板块支持拖动排序、自定义图标、可选通知徽标，以及独立的阅读和发帖等级限制。
- **图文编辑**：Editor.js 块编辑器采用中文界面，支持图片、引用、列表、代码、行内剧透和表情包。
- **内容管理**：发帖管理、发帖审核、个人回收站、管理员删除记录和按身份去重的浏览量。
- **站内消息**：向全体用户、指定用户组或 UID 发送公告与通知；回复帖子或被 @ 回复会收到“回复我的”通知，可按 20 条分页并跳转到对应回复，也可在“屏蔽管理”中按用户名屏蔽或撤销屏蔽通知。
- **举报处理**：帖子、主回复、楼中楼和用户资料提供举报入口；拥有 `posts.manage` 的管理员在“举报处理”中可隐藏、删除、删帖并封禁、删除回复、封禁用户或不处理。
- **外观与关于**：浅色、深色主题、强调色、紧凑导航和文字缩放；“关于”页展示项目介绍、版本及开源项目链接。

## 首页与板块图片

在“管理后台 → 内容管理 → 主页设置”修改社区首页和热门讨论的标题、说明，点击“保存设置”生效；首页和热门讨论背景图也在此分别上传或移除。热门讨论与各板块页可独立选择“固定半屏渐变”或“固定 3/4 屏渐变”，背景固定在内容视区上方，向下逐渐淡出为透明，滚动时仍可见。社区首页保留原有随头部滚动的背景方案及 3:1 裁剪。首页板块卡片等宽横排，超出可见区域后可用左右箭头或触摸横向滚动；鼠标在板块卡片区域向下滚动时，先横向滚至最后一张卡片完整显示，继续滚动才向下翻页；向上滚动同理。首页和板块页头部都不额外加外框。

板块地址使用路径标识，如 `/#/category/square`；帖子使用 `/#/category/square/post/{uuid}`。隐藏帖子使用 `/#/post/{uuid}`。旧板块数字地址及旧帖子链接会跳转到当前规范地址，帖子移动板块或路径标识更改后也按当前板块跳转。

在“管理后台 → 内容管理 → 板块结构”选择一个已创建的板块，即可上传、更换或移除自定义板块图标和头部背景图，并设置背景显示范围。旧板块和热门讨论默认半屏。先选择范围再上传，裁剪框会按半屏 8:3、3/4 屏 16:9 固定比例调整；切换范围立即保存，已有图片仅改变显示范围，需要重新构图时可更换图片。自定义图标用于板块导航、卡片和板块页；移除后使用原有内置图标。支持 PNG、JPEG、WebP、GIF；图标最大 2 MiB，背景图最大 10 MiB。

首页与热门讨论图片由 `settings.manage` 管理，板块图片由 `categories.manage` 管理。图片固定保存在 `apps/api/data/site-assets/`，通过 `/site-assets/<文件名>` 公开读取；不进入图床图库、不计入个人图床配额、不使用 S3 或自动回收。上传和移除立即生效；替换、移除图片或删除板块后清理不再使用的文件。备份和迁移时一并保留整个 `apps/api/data/` 目录。

## 用户、注册与邀请码

管理后台使用分层导航：“用户与注册”“内容管理”“站点配置”的父项只展开或收起子树，点击子项才打开页面。仅显示当前用户有权限的子项；没有可访问子项的分组不显示。导航窗格切换按钮位于 TitleBar 左侧，桌面可展开或折叠，窄屏可打开或关闭抽屉。

进入后台页面前会刷新当前权限；停留后台时每 30 秒以及重新切回浏览器页面时复核。权限组到期、权限撤销或账号被封禁后，对应菜单和已打开页面会移除。API 对每次请求独立执行权限检查。

### 邮箱验证与密码安全

“站点配置 → 发信设置”配置 SMTP 发信以及可选的 IMAP 收信连接检查。SMTP 负责发送邮件，IMAP 不用于发信。支持直接 TLS（常用端口 465）和 SMTP STARTTLS。填写发件身份、服务器、端口、账号和密码后保存，可发送测试邮件或检查 IMAP 连接。已保存的密码不回传前端，密码框留空会保留原凭据。

首次配置发信凭据前，在 `apps/api/.env` 设置 `MAIL_ENCRYPTION_KEY`。可以使用以下命令生成 32 字节 Base64 密钥，将输出保存为该环境变量；以后需要保留同一密钥以读取已保存凭据：

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

邮件凭据、Turnstile 私钥和用户 TOTP 密钥使用 AES-256-GCM 加密后保存在数据库中。请保留原 `MAIL_ENCRYPTION_KEY`；真实邮箱、服务器和凭据属于本地部署配置，不应写入源码、截图或 Git 仓库。

在“用户与注册 → 注册管理”启用注册邮箱验证后，注册需要先取得邮箱验证码。验证码默认有效 **60 分钟**；同一邮箱的注册、改密和找回邮件共用发送间隔，默认 **60 秒**，不能设置得更短。验证码一次性使用，输错 5 次后失效。

登录对话框提供“找回密码”。用户填写注册邮箱后会收到一次性找回链接，默认有效 **30 分钟**，同一邮箱每天最多请求 **1 次**；次数按站点时区计算。链接使用“站点设置”中的站点 URL，请将其设为用户实际能访问的地址。重设密码后，所有旧登录凭证失效。

用户后台的“更改密码”通过已绑定邮箱的验证码确认身份，新密码需为 10–128 位。默认每 **60 秒**最多成功修改一次。改密后保留当前登录，其他旧登录凭证失效。

验证码有效期、发送间隔、找回功能开关、链接有效期、每日找回次数及改密间隔均在注册管理中配置。注册邮箱验证默认关闭，以保留未配置邮件服务时的现有注册方式；启用前必须先配置发信服务。上述流程不会向已有账号补加登录邮箱验证要求。

用户可在“用户后台 → 资料管理”开启两步验证：输入当前密码后用身份验证器扫描二维码，并输入应用生成的 6 位验证码完成绑定。之后登录需先通过密码，再输入一次性验证码；启用或关闭时，其他登录会话失效。绑定密钥只在设置时显示，`MAIL_ENCRYPTION_KEY` 必须配置且在备份恢复时保留。请备份身份验证器中的账号；邮箱重置密码不会解除两步验证。

有 `settings.manage` 权限的管理员可在“用户与注册 → 注册管理”配置 Cloudflare Turnstile 站点密钥和私钥，并在 Cloudflare 为该小组件添加站点域名。开启后，登录、注册、注册验证码发送、找回密码申请、重设密码、改密验证码发送和提交新密码均需通过验证。私钥加密保存在数据库；留空私钥不会覆盖已保存的值。各表单的小组件居中显示，窄屏使用紧凑尺寸。

注册可以关闭、向所有人开放，或要求邀请码。管理员可以创建单次或多次使用的邀请码，设置等级奖励，并启用、停用或删除奖励规则。删除奖励规则后，已经发出的邀请码仍然保留。用户可从用户后台中的“我的邀请码”管理邀请链接；复制邀请与图片链接时使用配置的站点 URL。

用户可以上传头像、修改昵称和登录用户名。用户名不区分大小写，成功修改后需等待 180 天才能再次修改；有效管理用户组成员豁免此限制。失败的修改和保存相同用户名不占用次数。昵称独立修改，并用于顶栏、个人资料和帖子署名。更换用户名不会改变 UID、昵称或其他账号数据。

管理员可以将账号封禁 30 分钟至 1095 天，或提前解封。临时封禁期间仍可登录，以最低用户阅读等级 Lv.1 浏览，并查看自己的资料、帖子、收藏夹和图片。所有写操作（包括点赞、发帖、回复、收藏、上传、改资料和签到）及管理后台访问被禁止，到期自动恢复原权限。永久停用是独立状态，仍禁止登录。用户管理显示头像，并可按全部、正常、已封禁、已停用筛选，与搜索组合使用；正常包含已过封禁期限的账号。被封禁用户的空间顶部显示 Error InfoBar，注明封禁截止日期和时间。UID 1 的状态选择与封禁按钮不可用，API 同时拒绝停用或封禁请求。

## 正文限制、分页与本地草稿

在“内容管理 → 发帖与回复设置”配置以下限制，需要 `settings.manage` 权限。前后端共同校验，新设置用于之后提交的内容，不删改历史正文。

| 项目             | 默认值 | 允许范围 |
| ---------------- | ------ | -------- |
| 帖子正文字数     | 20000  | 1–100000 |
| 帖子正文普通图片 | 15     | 0–50     |
| 回复字数         | 1000   | 1–10000  |
| 回复普通图片     | 5      | 0–20     |
| 每页回复         | 20     | 1–100    |
| 每页帖子         | 20     | 10–50    |

社区首页、热门讨论和各板块的帖子列表在服务器分页，底部提供上一页、下一页及页码跳转；输入页码后也可按 Enter。页码和排序保存在 URL 中，刷新或返回后保留。切换排序回到第一页，超过末页的链接显示当前末页。标题旁的帖子数量是当前可阅读的总数，不只计算本页。每页帖子数在“内容管理 → 发帖与回复设置 → 帖子列表”调整。

`GET /api/posts?page=N` 返回 `{ posts, page, pageSize, total, totalPages }`；不带 `page` 的旧调用继续返回最多 60 篇的数组。列表先从索引选取本页 ID，再读取正文、作者和点赞统计；后半部分页码反向扫描，保留页码跳转入口。热门排序按未删除回复总数（含主回复和楼中楼）排列，置顶和首页关注未读优先规则保持不变。

带 `q` 的搜索继续返回最多 60 篇的数组，即使传入 `page` 也不会变成分页响应。服务器在同一只读快照中分批检查候选，收集满 60 篇正文可见部分或标题包含关键词的结果后停止；隐藏段落不能用于匹配。仅命中隐藏段落时仍可能扫描多批候选。

字数按 Unicode 字符计算，包含列表、引用、图片说明等可见正文，格式标记不占字数。图片上限只计算普通图片，用户上传表情、远端行内表情和社区表情不占此额度；所有表情合计固定最多 1000 个，每篇帖子、每条回复（含楼中楼）独立计数，重复插入也逐个计数。回复在服务器分页，帖子和回收站详情均支持翻页。

选中文字后，可在浮动菜单中设置斜体或点击遮眼图标添加剧透标记；有内容锁定权限的发帖编辑器还会显示锁图标，评论不提供内容锁定。插入表情使用编辑器底部的“表情”按钮。

编辑器中的待发正文、标题、板块、版权选择和图片仅缓存在当前浏览器 IndexedDB，按用户和回复目标隔离；刷新或返回页面可恢复，清除浏览器站点数据会删除草稿。选图时使用本地预览，提交帖子或回复时才将新图片与正文一起发送。验证、容量检查或保存失败会回滚图片文件与记录，草稿保留；提交成功后清除对应草稿。每次提交的新图片总大小最多 100 MiB，并受个人媒体额度约束。

从板块页点击“发布帖子”时，发帖页自动选择该板块，并优先于草稿保存的板块；草稿标题、正文和图片继续恢复。用户仍可手动更换板块。从普通入口进入时沿用草稿板块，无草稿时选择第一个允许发帖的板块；等级不允许的板块不能预选。

“我的图片”默认只能管理已上传的正文图片，不能直接上传图床图片。管理员可在同一设置页开启直接上传；头像和表情包仍使用各自的上传入口。

## 帖子版权声明

发帖时在正文下方选择“版权声明”，可预览发布后显示的图标和声明。默认“不适用”不附加声明；其他选项为 CC0、CC BY 4.0、CC BY-SA 4.0、CC BY-NC 4.0、CC BY-NC-SA 4.0、CC BY-ND 4.0、CC BY-NC-ND 4.0，以及“版权所有声明”。CC0 使用 1.0 公共领域贡献声明，其余 CC 选项使用 4.0 国际版；图标和协议名称均链接到对应的 Creative Commons 官方中文说明。

声明单独显示在帖子正文末尾，包含发帖人署名与所选协议的使用条件；“版权所有声明”标注版权归作者所有、转载或改编须经许可。声明不计入正文字数，也不应用于评论。审核阅读、作者查看待审帖子及个人回收站详情显示同一声明，恢复帖子后保留选择。

`POST /api/posts` 的 JSON 或 multipart `payload` 可传 `copyrightLicense`，取值依次为 `none`、`cc0`、`cc-by-4.0`、`cc-by-sa-4.0`、`cc-by-nc-4.0`、`cc-by-nc-sa-4.0`、`cc-by-nd-4.0`、`cc-by-nc-nd-4.0`、`all-rights-reserved`；省略时为 `none`。详情返回 `copyright_license`。迁移 `030_post_copyright.sql` 为历史帖子设置 `none`，不改动原正文或追溯授予许可。

## 回复、楼中楼与删除

在帖子回复下方点“回复”可展开楼中楼编辑器；回复某一条楼中楼时会显示被回复用户名。每个主回复每页显示 5 条楼中楼，提供上一页、下一页和页码跳转；分页只刷新当前楼层，不切换帖子回复页。每条主回复和楼中楼都有独立楼层号，格式为“第 12 楼”和“第 12 楼-3 层”。楼层分配按时间递增且不回收；永久删除后后续楼层号仍连续增长，历史编号不重新排列。已删除回复不显示楼层号，但保留其占用的编号。

普通用户只会看到自己回复上的删除按钮，并且只能删除自己发表的内容。拥有 `posts.manage` 的管理员可以删除任意回复。删除不进入回收站，也无法恢复；删除有楼中楼的主回复时可选择仅删除主回复（保留楼中楼，显示“该回复已被管理员删除”）或删除整层。管理员删除会向受影响作者发站内通知并写入管理记录；作者自行删除不会发送管理通知或写入管理员操作记录。删除最后一条楼中楼后，如果其主回复此前已删除，会一并清理空的删除占位。

## 关注与隐藏段落

在帖子作者旁或用户空间顶部资料卡右侧点“关注”，即可在“用户后台 → 我的关注”（`/account/following`）浏览关注的用户并进入其空间，也可取消关注。社区首页保留置顶帖优先，其后优先显示关注作者的未读帖子；登录后打开详情即计为已读，刷新、点赞和翻页不重复计数。已读帖子回到原排序，作者之后发布的新帖仍会优先。板块、搜索和热门讨论保留各自排序。

用户空间与个人资料共用资料展示：UID、UUID、等级、累计经验，然后显示所属用户组。用户空间下方保留帖子与公开收藏夹；两个页面均显示粉丝数，关注或取消关注后更新，个人资料可跳转用户后台。

在“用户后台 → 资料管理”依次管理头像、昵称、用户名和密码；点击用户后台头像或昵称旁的编辑图标也可快速修改。头像不出现在个人图库中，管理员图库仍可查看；原有存储计费和头像保护规则不变。

发帖时选中文字，右键选择“内容锁定…”，在对话框中选择“回复后解锁”“点赞后解锁”或“关注后解锁”。每段使用一种条件，可选择跨段文字；再次选中锁定文字可更改条件或移除锁定。草稿保留文字和条件。回复编辑器不提供内容锁定。

“用户组与权限”中的“隐藏段落”使用三状态复选框汇总三个子权限：`posts.hide_content.reply`（回复后解锁）、`posts.hide_content.like`（点赞后解锁）、`posts.hide_content.follow`（关注后解锁）。普通用户组默认拥有全部三项，也可分别授权。编辑器只显示已授权的条件，API 逐项验证。作者可阅读自己的全部内容；其他用户在有未删除回复（含楼中楼）、当前点赞或当前关注作者时解锁对应段落。取消点赞、取消关注或删除最后一条有效回复后，相应内容重新锁定。游客需先登录。此功能与点按即显示的“剧透”标记独立。

未解锁正文由 API 移除受保护文字、链接及其他属性。社区列表摘要、搜索、用户空间和收藏夹列表始终隐藏这些片段；满足条件后在帖子详情阅读。迁移 `015_follows_and_content_locks.sql` 创建关注关系；`025_granular_content_permissions.sql` 将已有隐藏段落授权展开为三个子权限，无授权的组保持不变。旧组权限 API 的 `posts.hide_content` 输入仍代表全部三项，返回及存储使用细分键。API 启动时自动迁移。

点击帖子正文图片可通过 hevue-img-preview 放大、缩放、旋转或切换正文中的其他普通图片。评论和楼中楼的图片只打开当前单图，不加入正文图库；表情和已删除图片占位不进入预览。也可用 Enter 或空格打开图片，Esc 关闭。

## 收藏与用户空间

用户后台的“我的收藏”按钮进入二级页面，可创建、重命名、删除收藏夹，设置是否公开，以及移动或取消收藏。每人最多 100 个收藏夹，名称 1–64 字。

在收藏夹列表点击“设为默认”，或在新建、编辑时开启“设为默认收藏夹”。每人最多一个默认夹；删除它后需要重新选择。未收藏时，帖子收藏拆分按钮左侧会快速保存到默认夹，未设置默认夹时打开选择菜单；已收藏时，再次点击左侧会从自己的所有收藏夹中移除此帖。右侧下拉菜单可单独选择其他收藏夹、取消收藏，或新建收藏夹。收藏到任一夹后，按钮显示强调色“已收藏”；全部取消后恢复普通色“收藏”。点赞使用切换按钮，点赞后显示强调色，刷新后保留状态。

点击帖子列表、帖子正文署名或回复的用户头像可打开 `/users/:uid` 用户空间。空间仅显示已发布且访客有阅读权限的帖子，以及公开收藏夹；隐藏、删除、待审和被拒绝帖子不会出现在空间和公开收藏中。私密收藏夹只有本人可读取。收藏夹公开内容也遵循访客阅读等级，公开计数不包含不可读帖子。

用户空间的帖子按站点“每页帖子”设置分页，支持上一页、下一页及页码跳转，输入页码后也可按 Enter。页码保存在 URL 中，刷新和浏览器返回会保留；超过末页时显示当前末页。

个人及公开收藏夹同样按站点“每页帖子”设置分页。`GET /api/favorite-folders/:id?page=N` 返回 `{ folder, posts, page, pageSize, total, totalPages }`，总数仅包含当前访客可阅读的已发布帖子；不带 `page` 的旧调用保留完整列表。空间和收藏列表复用帖子存储的回复总数。

`GET /api/users/:uid?page=N` 保留 `user`、`posts`、`folders` 字段，并增加 `page`、`pageSize`、`total`、`totalPages`，其中 `posts` 仅包含当前页。旧调用不带 `page` 时保留原响应及完整帖子列表；新调用应传入 `page`，避免一次加载全部帖子。

## 发帖管理与回收站

在“发帖管理”“发帖审核”“删除记录”中，可按标题、作者 UID、UUID、昵称或用户名搜索；发帖管理和发帖审核还可叠加状态筛选。标题、昵称和用户名按不区分大小写的字面子串匹配；UID、UUID 精确匹配。每页最多显示 25 篇，支持上一页、下一页和指定页码跳转，输入页码后也可按 Enter。搜索或状态变化后回到第一页，超过末页时显示当前末页。

这三个管理列表的 API 使用 `q` 和可选的 `page` 参数。带 `page` 时返回 `{ posts, page, pageSize, total, totalPages }`；不带 `page` 的旧调用仍返回数组，保留原 200 条上限。

作者可在用户后台将自己的帖子移入个人回收站。回收站中的帖子和原有回复仅作者可见，并从公开列表和发帖管理中排除。恢复后保留原有发布或审核状态、点赞和回复，不重复发放经验。

回收站默认保留 30 天，可在“站点设置 → 回收站”调整。新配置仅影响之后删除的帖子，已有到期时间不变。到期后立即停止访问与恢复；API 在启动时及之后每小时清理到期记录。图片仍由个人图床独立管理。

“发帖管理”中的隐藏操作会将帖子从首页、热门、搜索和板块列表中移除，持有 URL 的用户仍可在满足阅读等级条件时访问。管理员删除的帖子进入独立“删除记录”，仅拥有 `posts.manage` 的用户可恢复，不进入作者回收站，不自动到期，恢复时保留原状态。

`posts.set_reader_level` 控制是否可以为新帖设定大于 0 的最低阅读等级，前后端共同校验。管理组初始拥有此权限，普通组默认不拥有。

浏览量按登录账号或持有签名 `forum-visitor` Cookie 的游客浏览器去重。反复打开、刷新和点赞不会重复增加浏览量。登录身份和游客身份分开计数；更换浏览器或清除 Cookie 会形成新的游客身份。历史浏览总量保留，后续访问按新规则去重。

## 发帖审核与通知

在“审核设置 → 全站发帖审核”中启用新帖审核，也可在“板块结构”中单独为某一板块启用。更改设置只影响新提交的帖子，已有帖子和待审队列保持原状态。

审核规则按以下顺序应用：

1. 全局管理员发帖免审核。
2. 其余拥有 `posts.require_review`（发帖必须审核）的用户始终需要审核，即使同时拥有免审核权限。
3. 其余拥有 `posts.bypass_review`（发帖全局免审核）的用户可直接发布，包括开启审核的板块。
4. 其余用户在全站或当前板块启用审核时进入待审队列。

`posts.review` 授予发帖审核权限，可阅读正文，查看作者、发帖时间、当前用户组与提交 IP，并通过或填写原因拒绝。子权限 `posts.review.ban` 额外允许拒绝并临时封禁作者，必须同时拥有发帖审核权限。全局管理员固定拥有此子权限，其他审核组默认不授予，已有审核组升级后需按需单独勾选。历史帖子未记录提交 IP。拒绝和封禁会同时生成私有站内通知；临时封禁账号保持只读访问。

内置“站点管理”组初始拥有审核与免审核权限；新建管理组使用为其选择的管理权限。仅有 `posts.manage` 的用户不能通过发帖管理接口发布待审或被拒绝的内容。作者可通过帖子 URL 阅读自己的待审、被拒绝内容，审核员通过审核界面阅读。

用户组权限迁移会移除普通、公开组已有的管理权限，为管理组补齐三项基础用户权限，并将没有任何管理权限的旧管理组转为特殊组，保留成员关系与既有能力。移除授权和变更类型会记录在管理日志中。

拥有 `settings.manage` 的管理员可在“公告与通知”中向当前所有活跃账号、某个有效用户组的成员，或指定 UID 发出消息。用户在“站内通知”中阅读公告、审核结果和“回复我的”消息，可标记单条或全部已读、按 20 条翻页，并从通知直接打开帖子中的主回复或楼中楼。回复通知的发送者可在“屏蔽管理”中按用户名加入或撤销屏蔽；屏蔽后既有未读通知也不会继续出现在列表和未读计数中。未读徽标每 30 秒更新。新注册用户不会收到注册前发送的公告。

帖子、评论、楼中楼和用户资料旁边的“举报”链接会要求登录并填写理由。拥有 `posts.manage` 的管理员在“举报处理”中按 20 条分页处理：帖子可隐藏、删除、删除并封禁作者或不处理；用户可封禁或不处理；回复可删除或不处理。封禁仍遵守不能封禁首位管理员、自己或最后一位可管理管理员的保护规则。

帖子作者可以举报自己帖子下由他人发布的回复。举报中的删除回复沿用回复管理：有子回复时保留已删除主楼占位，无子回复时永久删除，同时通知作者并写入删除与举报处理记录。

## 图床与表情包

“图床与表情 → 上传与远端设置”可调整默认限额：每用户 1 GiB、单图 20 MiB、20 组个人表情包、个人上传每组 150 张、单张表情 3 MiB。用户组可覆盖各项限额；多个有效组同时配置时，每项取最大值，未覆盖项使用站点默认值。`media.use` 控制个人图床管理与上传权限，普通成员默认拥有。

“图床与表情 → 存储设置”显示本站在每个存储后端的已用、剩余和容量，以及服务器各逻辑磁盘的剩余空间。管理员可设置本地最大可用容量、优先使用本地或对象存储、对象存储的本站配额，以及空间不足时每批回收的普通图片容量（默认 500 MiB）。本地容量设为 0 时使用上传目录所在磁盘的可用空间；优先后端没有足够空间时自动切换到另一个已启用后端。

对象存储支持兼容 S3 的 API。填写端点、Bucket、区域、路径前缀、Access Key、Secret Key 和本站配额后，可先执行连接测试，再保存设置。凭据使用 `STORAGE_ENCRYPTION_KEY` 加密保存；未设置时复用 `MAIL_ENCRYPTION_KEY`。每个文件会记录上传时使用的对象存储配置，因此修改或关闭当前配置不会使已有图片地址失效。对象存储容量按管理员填写的本站配额统计，不会把同一 Bucket 中其他应用的对象算入本站。

“对象存储图片访问方式”支持三种方式，默认使用服务器转发：

- **服务器转发**：由网站服务器读取并返回图片，兼容私有存储桶。
- **预签名 URL 直连**：本站图片地址临时跳转到有效期 15 分钟的 S3 预签名链接，浏览器直接从对象存储获取图片，兼容私有存储桶。S3 API 端点必须可被用户访问；链接过期后重新访问本站图片地址即可获取新链接。
- **自定义域名公开访问**：填写映射到当前存储桶根目录的公开地址，如 `https://images.example.com`，也可包含路径。系统会附加图片实际对象键（包含对象路径前缀），请勿重复填写前缀。需预先在存储服务中启用公开读取或配置 CDN，保存设置不会修改存储桶权限。

两种直连方式仅由本站返回不缓存的临时跳转，图片数据不经过网站服务器。帖子、头像等继续保存稳定的 `/uploads/<文件名>` 地址；切换访问方式或签名过期无须修改旧内容。保存时同步更新同一端点和存储桶中已有图片的访问方式；更换端点或存储桶后，旧图片继续使用原位置配置。本地图片及 `site-assets` 社区图片不受影响。HTTPS 网站应配置 HTTPS 端点和公开访问地址。原“测试对象存储连接”仍检查 S3 API 的上传、读取、删除权限，公开域名或 CDN 的配置需通过实际图片访问确认。

未启用对象存储时，本地存储或所在磁盘使用率达到 95%，系统向拥有 `media.manage` 的有效管理员发送站内提醒；对象存储配额使用率达到 95% 时同样提醒。提醒每个后端每天最多发送一次，容量恢复后会重新进入提醒周期。所有已启用后端都放不下新图片时，系统从最早上传的普通图片开始按设定批量回收，并将正文中的引用替换为删除占位图；每批至少释放设定容量，可回收图片不足时释放剩余可回收空间。表情包、头像和站点图标永不参与自动回收。回收会写入管理记录，S3 删除失败时会保留待删除队列，后台维护任务会重试。

“我的图片”支持已上传图片的说明编辑、链接复制、个人表情包及远端表情包收藏。个人表情包仅出现在作者的编辑器选择器中。删除自有图片时，现有帖子和回复中的对应图片位置会替换为阿卡林占位图，其他图片和说明保持原样；删除个人上传的表情包也会替换对应引用。当前头像与站点图标受到删除保护。

在“我的图片 → 我的表情包”查看分组预览，用“上移 / 下移”保存个人分组顺序。编辑器选择器使用 PipsPager 切换分组，指针在面板内滚动滚轮可切组。超过 20 张的组先在组内滚动，到顶或到底后继续同向滚动一段距离才切换至上一组或下一组，切组后会抑制惯性连续跳组。悬停或聚焦表情时显示名称。

远端表情插入在当前光标处，与文字同行，高度为当前字号的两倍（正文默认约 30px）。可连续插入、逐个退格或 Delete 删除，支持撤销和草稿恢复；个人上传表情继续作为 80px 独立块显示。行内表情计入每篇正文固定 1000 个的表情限额，服务端校验缓存图片身份。已有远端表情块由迁移 014 标识，展示时接在前一段文字后；已有个人上传表情保持原样。

远端下载默认关闭，可在后台启用并配置兼容的 [Bmoji](https://github.com/SomeOvO/Bmoji) API。支持搜索、预览及静态/GIF 版本导入。同一来源、表情包和版本共用本地缓存，用户通过独立收藏关系使用，不计入个人图床容量。远端每组图片数由远端服务器管理，不受个人上传每组 150 张限制。“用户下载的远端表情包计入个人组数限额”默认开启；关闭后只统计个人上传组，重新开启不会移除已有分组，超额用户须先移除分组才能继续添加。移除个人收藏不会删除共享缓存或影响帖子中的表情。

远端表情先下载到临时目录，准备完成后再提交共享缓存，下载期间普通上传可继续进行。每个 API 进程最多同时准备两组，每组同时下载三张图片，每张仍限制为 3 MiB；导入请求上限为 34 个（含等待），超过时返回 503。共享缓存提交时重新检查组数限额，失败时回滚文件和订阅关系。

管理员在“图床与表情”选择一组已有共享分组，或在“上传与远端设置”从远端下载并设为社区表情包。社区组只有一组，固定排在选择器第一位，不占任何用户的个人组数限额，用户不能排序或移除。未设置或没有图片时不显示该组。有 `posts.create` 或 `replies.create` 权限的用户可在对应发帖、回复编辑器使用，无须 `media.use`。迁移会沿用首个已有图片的共享组，初始空组保持隐藏。

“图片管理”支持按文件名、图片说明、表情包名称搜索，并与资源类型和分组筛选组合使用，默认每页 50 张。分页接口为 `GET /api/admin/media/search`，支持 `q`、`collection`、`packId`、`page` 和 `pageSize`；原媒体列表接口保留数组返回格式。

“我的图片 → 个人上传”每页显示 50 张，支持上下页、页码跳转、Enter 和 URL 页码恢复。`GET /api/me/media?page=N` 返回 `{ items, page, pageSize, total, totalPages }`，仅包含本人的非头像资源；`collection` 可组合筛选。`GET /api/admin/media?page=N` 使用相同分页结构并保留管理员的全部资源范围。两者不带 `page` 时仍返回原完整数组。迁移 `032_personal_list_indexes.sql` 为收藏夹和个人图片增加分页排序索引，启动时自动应用。

## 开发与验证

前端位于 `apps/web`，后端位于 `apps/api`。应用使用 WinUIonWeb 的 TitleBar、NavigationView、Frame、表单、对话框、树和主题资源。路由采用 Hash 模式，可以直接链接帖子、板块和管理页面；管理菜单按用户有效权限显示。

点击导航子项后，已展开的分组保持展开；权限和未读数量刷新也保留手动展开、收起的状态。权限撤销时，对应菜单项仍会立即移除。

热门讨论直接展示帖子列表，不显示顶部板块卡片或发布帖子按钮；社区首页和分类页保留板块及发帖入口。

Windows 使用本机 Segoe Fluent Icons，其他系统在挂载页面前加载本地 Fluent UI System Icons，覆盖业务和控件图标，无需安装字体。新增图标需同时维护两套图标的对应关系，`npm run check` 会检查映射；维护方法见[跨系统图标](icon-compatibility.md)。

```powershell
npm run check
npm run build
npm run test:integration -w apps/api
```

集成测试使用已配置的 PostgreSQL 数据库创建临时 schema，并在运行后移除，覆盖注册、邀请码、媒体权限与限额、共享远端缓存、用户组约束、封禁、审核、通知、占位图片和回收站隔离。测试数据库账号需要创建 schema 的权限。

前端格式化命令为 `npm run format -w apps/web`。独立前端验收实例可通过 `FORUM_API_URL` 将 Vite 代理指向独立测试 API。
